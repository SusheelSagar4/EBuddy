# EBuddy Web UI Shell & API Documentation

## 1. Architecture & Design Principles

The EBuddy Web UI shell is designed for zero-outbound air-gapped environments, strict accessibility, and deterministic curriculum traceability.

- **Air-Gapped / Zero Outbound:** Absolutely no external Content Delivery Networks (CDNs), no external JavaScript libraries, and no external web fonts (e.g. Google Fonts). All styles and scripts are locally vendored under `app/static/css/style.css` and `app/static/js/app.js`.
- **Zero Build Step:** Plain HTML5 + vanilla ES6 JavaScript + semantic CSS served directly by FastAPI via `StaticFiles` and `Jinja2Templates`.
- **Traceability & Badges:** Every course, exercise, resource, and goal prominently displays its canonical Knowledge Base code (e.g., `EE3L004`, `EX_EE_001`, `GOAL_EE_CORE_POWER`) and its provenance status badge (`verified` or `draft_for_review`).
- **Persistent Evaluation Banner:** A prominent top-level alert (`SYNTHETIC PROFILE • DRAFT DATA`) is rendered across all pages.
- **Single-Writer Governance:** The UI enforces the four-agent architecture: Agents 2, 3, and 4 generate `ChangeProposal`s; student review and approval triggers re-planning exclusively through Agent 1 (Roadmap Planner).

## 2. Web UI Pages

| # | Page Route | Name | Purpose & Features |
|---|---|---|---|
| 1 | `/` | **Home (Student Profile)** | Choose a synthetic student persona from `data/seed/personas/*/students.csv` (EE & MME); displays branch, semester, CGPA, backlogs, and verified completed course history. |
| 2 | `/goals` | **Goal Selection** | Filter specializations by the student's branch plus cross-branch pathways (`SDE/Data`, `UPSC`, `Tech Startup`). Provides "Build my roadmap" action. |
| 3 | `/roadmap` | **Academic Roadmap** | Semester-by-semester curriculum plan generated by Agent 1. Displays course code, title, credits, skill-gap rationale, verification badges, institutional warnings, and pending proposals. |
| 4 | `/diagnostic` | **Adaptive Diagnostic** | Computerized Adaptive Testing (CAT) driving `app/engine/diagnostic.py` (one question at a time). Displays progress indicator, difficulty adjustments, and final $\theta$ ability score with confidence spread. |
| 5 | `/chat` | **Tutor Chat & Advisory** | Interactive query box routing through `IntentRouter` -> `Explainer` via `app/llm/client.py`. Displays clear "LLM not configured" notification if using placeholders; cites KB codes beneath each answer. |
| 6 | `/approvals` | **Change Proposals** | Review pending proposals submitted by Agents 2, 3, and 4 (workload reduction, remediation, credit overload). Student approval triggers Agent 1 to commit Roadmap Version $N+1$. |
| 7 | `/admin` | **System Status & KB Explorer** | System health panel (DB healthy, LLM configured, row counts), internal link to Adminer (`:8080`), read-only viewer for key KB tables, and a "Reload Seed Data" button. |

## 3. JSON API Endpoints (`/api/...`)

The backend exposes clean REST endpoints wrapping the underlying domain services without mixing UI or business logic into routes:

### Health & System
- `GET /api/health` (also `GET /health`): Returns system status, database connectivity, and `llm_configured` flag (`bool`).
- `GET /docs`: Interactive OpenAPI documentation.

### Student & Goals
- `GET /api/students`: Lists all synthetic student profiles from `data/seed/personas/*/students.csv`.
- `GET /api/students/{student_id}`: Returns academic profile and completed courses for a student.
- `GET /api/goals`: Returns career goals, optionally filtered by `?programme_id=BTECH_EE` or `?programme_id=BTECH_MM` along with cross-branch goals.

### Academic Planning & Roadmap
- `POST /api/roadmap/generate`: Body `{ student_id: str, goal_id?: str }`. Invokes Agent 1 to generate and commit baseline Roadmap Version 1. Returns enriched plan items with titles, credits, badges, and warnings.
- `GET /api/roadmap/{student_id}`: Returns the current active roadmap plan for the student.

### Computerized Adaptive Diagnostic (CAT)
- `POST /api/diagnostic/start`: Body `{ student_id: str, goal_id?: str }`. Initializes or resets an adaptive assessment session.
- `GET /api/diagnostic/{student_id}/next`: Retrieves the next adaptive exercise item (one question at a time) or signals completion.
- `POST /api/diagnostic/{student_id}/answer`: Body `{ exercise_id: str, skill_id: str, student_answer: str }`. Evaluates response, adjusts running ability $\theta$, updates standard error, and returns immediate feedback.

### Conversational Tutor Chat
- `POST /api/chat`: Body `{ student_id: str, message: str }`. Routes query through IntentRouter and Explainer. If model key is not configured, gracefully falls back to deterministic institutional responses with a clear banner. Always cites referenced KB codes.

### Governance & Proposals
- `GET /api/proposals/{student_id}`: Lists all pending `ChangeProposal` records for the student.
- `POST /api/proposals/{student_id}/{proposal_id}/decide`: Body `{ approve: bool, feedback?: str }`. Processes student decision; on approval, triggers Agent 1 to commit Roadmap Version $N+1$.

### Administration & Database Explorer
- `GET /api/admin/status`: Returns database status, LLM configuration flag, and row counts across core tables.
- `GET /api/admin/tables`: Returns list of viewable tables (`kb.course`, `kb.programme_requirement`, `kb.skill`, `kb.goal`, `kb.exercise`, `kb.resource`).
- `GET /api/admin/tables/{table_name}`: Returns the top 50 records of the selected table.
- `POST /api/admin/reload-seed`: Executes `scripts/seed_loader.py --reset` to reload knowledge base seeds.
